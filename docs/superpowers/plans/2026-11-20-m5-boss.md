# M5 — First Boss Encounter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one boss encounter that requires the player to use movement, evolution and timed energy-managed bursts, closing Phase 2's last open item.

**Architecture:** A new `BloomBoss` node owns its own state machine and damage gating; it joins the existing `predator` group so `PlayerController.spike_burst()` can hit it without any change to `player.gd`. A dedicated `BossFight` scene owns the arena, evolution gate, shelter retry, HUD and demo autopilot. Room-drawing helpers move into a small `RoomBuilder` because the boss scene is the third consumer of the same geometry.

**Tech Stack:** Godot 4.7.2 stable, GDScript, headless `--script` regression checks, PowerShell runners.

**Spec:** `docs/superpowers/specs/2026-11-20-m5-boss-design.md` (read alongside this plan; every value below is **Proposed**, not owner-approved).

## Global Constraints

- Godot **4.7.2 stable only** (`4.7.2.stable.official.ed1daf0bf`); engine is not on `PATH`, so commands take an explicit `$godot`. On Windows use the `_console.exe` build.
- Run all commands from the repository root; engine arguments go before `--`.
- Project root `game/`; base viewport **960×540**, stretch `canvas_items`, aspect `expand`, renderer `gl_compatibility`.
- Files/folders `snake_case`; scene root nodes `PascalCase` matching the file; one script per scene where 1:1.
- Input only through action names in `game/project.godot` (`Input.is_action_pressed` / `event.is_action_pressed`); never raw keycodes.
- No new dependencies, no new resource types, no save-format expansion. `save_state.gd` keeps only `evolved` and `nutrition`.
- No audio assets and no frame-by-frame animation in this milestone; feedback is procedural, as in M2–M4.
- Progression safety: an unevolved player must never reach an unwinnable fight; energy must always regenerate to full without pickups.
- Every task that changes code must leave `pwsh -File harness/scripts/check.ps1` reporting `HARNESS CHECK PASSED`.
- Do not mark any milestone PASS in `docs/MILESTONES.md` — that is the owner's decision after playtest.

## Review Focus

- **Burst spam outside the weak window** — a held `J` must not kill the boss; pinned by `tests/boss_check.gd` case "damage only while exposed".
- **Starved or cooldown-blocked burst** — must spend no energy and deal no damage; pinned by the same file's "refusal has no side effects" case (reuse `tests/energy_check.gd` pattern).
- **Unevolved player at the gate** — must see a dormant bloom, not an impossible fight; pinned by `tests/boss_check.gd` case "gate blocks unevolved".
- **Retry must not erase progress** — evolution, nutrition and consumed motes persist while boss health and energy reset; pinned by "shelter retry" case.
- **Room extraction must not change M0–M3 behavior** — pinned by `pwsh -File tools/verify.ps1 -Godot "$godot" -SkipDemo` plus both scene smokes after Task 2.

### Task 1: `BloomBoss` state machine and damage gating

**Files:**
- Create: `game/scripts/bloom_boss.gd`
- Test: `game/tests/boss_check.gd` (cases 1–7 added here; more cases in Tasks 2–3)

**Interfaces:**
- Consumes: `PlayerController` (`take_damage(amount: int, from_pos: Vector2) -> bool`, `global_position`), group name `"predator"` from `predator.gd`.
- Produces: `class_name BloomBoss extends CharacterBody2D` with `const MAX_HEALTH := 6`, `const ATTACK_DAMAGE := 1`, `const TELEGRAPH := 0.6`, `const WEAK_WINDOW := 1.5`, `const RADIUS := 60.0`, `const GROUP := "predator"`; signals `defeated` and `phase_changed(phase: String)`; members `player: PlayerController`, `health: int`, `defeated: bool`, `phase: String`; methods `set_player(p: PlayerController) -> void`, `take_damage(amount: int) -> bool`, `is_vulnerable() -> bool`, `phase_name() -> String`, `reset() -> void`.

- [ ] **Step 1: Write the failing test cases**

In `game/tests/boss_check.gd`, following the `extends SceneTree` pattern of `game/tests/energy_check.gd`, add helpers `_frames(n)`, `_check(label, ok, detail)`, `_make_player(pos)`, `_make_boss(pos, player)` and these cases:
  - `exposed window is the only vulnerable phase` — start at `phase == "exposed"`, assert `take_damage(1) == true` and `health == MAX_HEALTH - 1`; then force `phase = "telegraph"` and assert a second `take_damage(1) == false` and health unchanged.
  - `refusal deals no damage and emits nothing` — from `phase == "idle"`, assert `take_damage(2) == false`, health unchanged, `defeated == false`, signal count 0.
  - `defeat emits once and freezes the boss` — set `health = 1`, phase exposed, call `take_damage(1)` twice; assert exactly one `defeated` emission, `defeated == true`, `health == 0`, and `take_damage(1) == false` afterwards.
  - `player is hurt only during the attack phase` — place player inside `RADIUS`, set `phase = "attack"`, advance one physics frame, assert `player.health == PlayerController.MAX_HEALTH - 1`; reset player with `revive()`, set `phase = "exposed"`, advance frames, assert health unchanged.
  - `reset restores health and phase` — after defeating, call `reset()`, assert `health == MAX_HEALTH`, `defeated == false`, `phase == "idle"`.
  - `a fired burst in the exposed window spends exactly one energy and one boss health` — evolved player at boss distance `<= PlayerController.BURST_RANGE`, boss in `exposed`, measure energy before, call `player.spike_burst()`, assert boss health dropped by `BloomBoss` damage 1 and energy dropped by exactly `PlayerController.BURST_ENERGY_COST`.
  - `starved and cooldown bursts have no side effects` — with `player.evolved = true` but `player.energy = 0`, call `spike_burst()`, assert `false`, boss health and energy unchanged; then restore energy, fire once, immediately fire again inside the 0.8 s cooldown and assert no second boss-health or energy loss.
  Set `const EXPECTED_CASES := 7` for now and print `ALL PASS` / `FAIL` with exit code 0/1 exactly as `energy_check.gd` does.

- [ ] **Step 2: Run the tests to confirm they fail**

Run: `$godot = "<path to Godot_v4.7.2-stable_win64_console.exe>"; & $godot --headless --audio-driver Dummy --path game --script res://tests/boss_check.gd`
Expected: exit 1 with parse/access errors for the missing `BloomBoss` identifier.

- [ ] **Step 3: Implement `game/scripts/bloom_boss.gd`**

One script, state machine `idle (0.4 s) -> telegraph (TELEGRAPH) -> attack (0.25 s) -> exposed (WEAK_WINDOW) -> idle`. Alternate `lash` and `spore` attack names each cycle and include the name in `phase_changed`. Emit damage at most once per attack phase and only when `player != null`, `not player.dead` and `global_position.distance_to(player.global_position) <= RADIUS`. Accept damage only when `phase == "exposed"` and not `defeated`; emit `defeated` exactly on the transition to zero health. `reset()` restores all state. Join `GROUP` in `_ready()` so `spike_burst()` can find it. Build a procedural gradient visual (larger and clearly different from `predator.gd`), pulse faster in telegraph, dim in exposed, fade out after defeat. Use `PROCESS_MODE_PAUSABLE` so pause freezes the fight, matching M4.

- [ ] **Step 4: Run the tests to confirm they pass**

Run: `& $godot --headless --audio-driver Dummy --path game --script res://tests/boss_check.gd`
Expected: `ALL PASS`, exit 0, 7 cases.

- [ ] **Step 5: Commit**

```powershell
git add game/scripts/bloom_boss.gd game/tests/boss_check.gd
git commit -m "test(boss): add weak-window damage gating and state machine"
```

### Task 3: Boss arena scene — gate, shelter retry and HUD

**Files:**
- Create: `game/scenes/boss_test.tscn`, `game/scripts/boss_fight.gd`
- Modify: `game/tests/boss_check.gd` (add gate and retry cases)

**Interfaces:**
- Consumes: `RoomBuilder.build_room`, `BloomBoss` (Task 1), `PlayerController.evolve()/revive()/evolved`, `EvolutionZone`, `Absorbable`, `SaveState.DEFAULT_PATH`, `Predator.GROUP`.
- Produces: `class_name BossFight extends Node2D` with constants `ROOM`, `BOSS_START`, `GATE_X`, `SHELTER_POS`, `M5_SHOTS := ["approach", "telegraph", "weak-window", "victory"]`; members `player: PlayerController`, `boss: BloomBoss`, `boss_defeated: bool`; methods `gate_open() -> bool`, `retry() -> void`. `evaluate_m5_demo(...)` is added in Task 4.

- [ ] **Step 1: Write the failing gate/retry cases**

Add to `game/tests/boss_check.gd`:
  - `gate blocks an unevolved player` — instantiate `BossFight`, set `player.nutrition = 0`, advance 2 frames, assert `gate_open() == false`, `boss.player == null`, and that the boss does not take damage from `player.spike_burst()`.
  - `gate opens after evolution` — set `player.nutrition = player.EVOLVE_COST`, call `player.evolve()`, advance frames, assert `gate_open() == true` and `boss.player == player`.
  - `shelter retry resets the fight but keeps progress` — open the gate, damage the boss to 2 health and feed the player to `nutrition = 42`, call `player.take_damage(PlayerController.MAX_HEALTH, Vector2.ZERO)` then `retry()`, assert `player.health == PlayerController.MAX_HEALTH`, `is_equal_approx(player.energy, PlayerController.MAX_ENERGY)`, `boss.health == BloomBoss.MAX_HEALTH`, `player.evolved == true`, `is_equal_approx(player.nutrition, 42.0)`.
  Bump `EXPECTED_CASES` to 11.

- [ ] **Step 3: Build the scene and script**

Create `boss_test.tscn` with root `BossFight` (script attached) and an instanced `PlayerController` named `Player`. In `_ready()`, parse `--fresh-save` and `--m5-demo`, load `SaveState`, build room via `RoomBuilder`, place one `Absorbable` mote and one `EvolutionZone` before the gate so the scene is self-contained, place `BloomBoss` past `GATE_X`, add a `StaticBody2D` gate and a camera following the player.
